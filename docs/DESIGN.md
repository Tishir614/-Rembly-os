# Оформление «Fox Mono»: чёрно-белое, по логотипу

- **Логотип** — лисица из вашего изображения (`assets/logo-fox-source.jpg`): белые линии на прозрачном фоне. Надпись **REMBLY OS** нарисована отдельно (`tools/gen_brand.py`): угловые буквы с острыми срезами и стыками, в том же языке, что уши и усы лисицы. Используется на заставке загрузки, в «О планшете», на экране блокировки (знак), в верхней панели (знак), как аватар и призрачным силуэтом на обоях.
- **Фон и стиль**: чёрный, белая «линейная» графика, тонкая белая рамка у плиток и окон (рамки окон — тема xfwm4 «Rembly», `tools/gen_wmtheme.py`), кнопки — тёмные с белым контуром и двойной фаской, нажатие инвертирует цвета. Обои — чёрные с призраком лисицы, кольцами и тонкими линиями (`tools/gen_wallpaper.py`; свою картинку можно положить в `~/.config/rembly/wallpaper.png`).
- **Иконки приложений** — по образцу второго изображения (`assets/icon-style-reference.jpg`): тёмный скруглённый квадрат со светлой рамкой, внутренней канавкой и белым значком. Значки берутся из системной темы: если у иконки есть символическая (монохромная) версия — она, иначе цветная иконка превращается в белый контурный рисунок (тёмная половина тонов вырезается). Это **не те же самые картинки**, что на образце (там игровые пиктограммы), а тот же вид и цвет для значков ваших приложений. Результат кэшируется на диске.
- **Верхняя панель** из «пилюль» (логотип + точки рабочих столов, медиа, трек, CPU/RAM, трей, сеть, громкость, часы), плитки на рабочем столе (карточка в стиле fetch, столбики как в cava — двигаются только пока играет звук, плитка приложений).
- Шрифт интерфейса панели и терминала — Fira Code; терминал и все приложения Rembly в той же чёрно-белой гамме.

Что отличается / ограничения (честно):
- Экранная клавиатура Onboard использует свою тему (тёмно-серая), полностью чёрно-белой она не перекрашена.
- Реальной прозрачности и размытия окон нет (композитор отключён ради скорости): панели Rembly «размывают» обои сами, чужие окна непрозрачные.
- Надпись — моя векторная прорисовка в стиле логотипа, а не готовый шрифт; сам знак лисицы — векторизация вашего JPEG (мелкие артефакты сжатия сглажены).
- Название в надписи — «Rembly OS» (как вы написали); в командах, путях и части подписей интерфейса остаётся рабочее имя `rembly`.

## Загрузка с атмосферой (0.26)
Заставка теперь **анимирована** (чёрно-белая, без GPU; кадры генерирует `tools/gen_bootanim.py`):
- **Вступление** (stage 1, один раз, ≈1,5 с): тонкое кольцо вычерчивает себя, лисица проявляется сверху вниз, глаза вспыхивают с ореолом, буквы REMBLY OS появляются по одной, из темноты проступает «пыль».
- **Петля** (stage 2, пока система запускается): глаза «дышат», от лисицы расходятся два кольца, по надписи бежит световая полоса, пылинки плавают; внизу — полоса прогресса по этапам запуска. Петля заканчивается ровно на кадре вступления, швов нет, и обрывается, когда стартует рабочий стол.
- Проигрыватель (`rembly-bootanim`) — это `gunzip | dd` в framebuffer на busybox: никаких лишних зависимостей. Если формат framebuffer другой или кадров нет, он просто ничего не делает, загрузка от него не зависит. Кадры петли идут в rootfs (≈1,6 МБ), вступление — в загрузочный образ (+≈0,7 МБ).
- Ограничения: скорость кадров на реальном планшете я не измерял (на хосте весь ролик вступления проигрывается за 0,25 с без задержек между кадрами; между кадрами стоит пауза 0,12 с, на A53 запись кадра займёт заметно дольше, поэтому петля будет менее плавной), а совпадение формата framebuffer (800×1280, 32 или 16 бит) — предположение, проверенное лишь на уровне байт в тесте.

## Стиль «Хакер» (0.28)
Второй стиль поверх того же оформления: `~/.config/rembly/style` = `hacker` (или `rembly-style hacker`). В `remblyui.py` стиль читается один раз при запуске (`STYLE`, `HACKER`, `ACCENT`), поверх основного CSS загружается `HACKER_CSS` (приоритет USER+1, поэтому перекрывает собственные правила приложений), рисованные виджеты берут цвет из `ACCENT`, значки-«белые глифы» перекрашиваются умножением на цвет акцента (кэш плиток отдельный: `m1h`), встроенные обои окрашиваются при загрузке (обои пользователя не трогаются). Остальное, что не относится к GTK-коду Rembly, переключает скрипт `rembly-style`: тема xfwm4 (`Rembly-Hacker`), `gtk.css`, цвета терминала, уведомления dunst, цвета строки приглашения. Рамки окон генерируются тем же `tools/gen_wmtheme.py --hacker` (яркость серого → зелёный канал).

Цифровой дождь (`remblyui.MatrixRain`): постоянная ARGB-поверхность; за кадр — одна заливка затухания (`DEST_OUT`, 13 %) и по одному новому символу на столбец из заранее нарисованного атласа (белый «головной» и зелёный «хвостовой» варианты); таймер идёт только между `start()` и `stop()` и пропускает кадры при `system_busy()`. Символы — латиница, цифры, знаки и несколько кириллических букв (в Fira Code нет катаканы, а шрифтов с ней в образе нет).

## Плеер и редактор (0.28)
Оба приложения используют тот же набор виджетов `remblyui` и работают в обоих стилях. Rembly Player (`rembly-player` + `rembly_media.py`) держит один процесс mpv, которым управляет по JSON IPC: музыка — без окна, видео — встроен через `--wid` (касания приходят из mpv как `script-message`, потому что дочернее X-окно mpv забирает события мыши у GTK). Фото рисуются сами: окно один раз уменьшает картинку «под размер» (при показе без увеличения перерисовка — обычный blit), крупное изображение используется только при увеличении. Rembly Code — GtkSourceView 4 + VTE: схемы `rembly` и `rembly-matrix` лежат в `usr/share/rembly/gtksource/styles/`.

Что проверено на ПК (Xvfb, mpv 0.37, GTK 3.24, Python 3.12) и чего нет на планшете: запуск, подсветка, поиск, терминал, F5, воспроизведение (звук — заглушка `--ao=null`), эскизы, обложки, волна, MPRIS через `playerctl`, жесты мыши. **Не проверено на устройстве**: звук (есть ли ALSA-карта), частота кадров видео, мультитач-щипок, расход процессора дождём и волной, поведение mpv 0.32 из Ubuntu 20.04 (на ПК другая версия: опции проверены по документации), реальный VS Code.

## ИИ и серверы (0.29)
- `rembly_ai.py` — логика без GTK: настройки (`ai.json` 0600, запасной вариант `/etc/rembly/ai.conf`), клиент со стримингом (SSE) для OpenAI-совместимых серверов и Anthropic Messages API, понятные русские сообщения об ошибках (401/404/429/нет связи/таймаут; ключ в сообщениях не появляется), повторы без `temperature` или с `max_completion_tokens`, если сервер их не принимает; разбор ответов (`<file path>`, блоки кода, план проекта JSON), проверка путей (`safe_rel`, `check_files`: только внутри проекта, без `.git`, без секретных имён, лимиты), чёрный список команд (`DENY`), резервные копии при записи (`write_files`). `rembly_aiui.py` — окна и панель. Проверено поддельным сервером (56 проверок логики) и сквозным сценарием в GTK (настройки → чат с контекстом → применение файлов → Ctrl+K → мастер проекта); с настоящими Claude/OpenAI/Ollama не проверялось: нет ключей и сети к ним.
- Проект создаётся пошагово (план JSON, затем отдельный запрос на каждый файл с кратким контекстом уже написанного), а не одним огромным ответом: так надёжнее для маленьких локальных моделей и не упирается в предел токенов. Ограничение: связность файлов зависит от модели.
- `rembly_term.py` — общий терминал (Vte в системных цветах, спавн для Vte 0.60 и новее, чтение вывода для «ошибка из терминала», настоящие события клавиш для стрелок/Home/End, залипающие Ctrl/Alt). `rembly_servers.py` — подключения и команды без GUI (адрес и имя пользователя проверяются, команда собирается списком, оболочка не участвует). `rembly-ssh` проверен с настоящим sshd на ПК (подключение по ключу, команды, переподключение, sshfs); RDP/VNC/serial проверены только на уровне собираемых команд. Образ armhf: Python 3.8, GtkSource 4.6, Vte 0.60 (запуск проверен под qemu).


Тесты логики без сети и без планшета: `python3 tests/test_rembly_ai.py` (поддельный сервер OpenAI/Anthropic) и `python3 tests/test_rembly_servers.py`.
